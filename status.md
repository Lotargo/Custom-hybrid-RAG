# Текущий статус разработки SonataDB (Адаптировано под Windows / Кроссплатформенность)

В соответствии с новыми приоритетами, главная цель на текущем этапе — **обеспечить полную кроссплатформенную совместимость и запуск под Windows**, отказавшись от преждевременной оптимизации (квантование, SPDK, распределенность).

---

## 🟢 Что уже сделано и переносимо (Работает / Готово к тестам)

### 1. Математическое ядро (Core Math)
*   **Базовые скалярные метрики:** Вычисление Dot Product, L2 Distance и Cosine Similarity для арифметических типов данных с использованием концептов C++20. Полностью переносимы.
*   **Векторизация AVX2 & AVX-512:** Оптимизированные версии функций расстояний для векторов `float32`. Работают как под Linux (GCC/Clang), так и под Windows (MSVC) через интринсики.

### 2. Поисковые индексы (Retrieval Engine)
*   **Векторный граф HNSW:** Потокобезопасная вставка, сериализация и десериализация графа. Архитектурно готовы к кроссплатформенной работе, завязаны на переносимый `MmapFile`.
*   **Tombstoning & Graph Compaction:** Логика удаления через `Roaring Bitmaps` и фоновое сжатие графа.
*   **Лексический индекс (BM25):** Инвертированный индекс со стеммингом (`libstemmer`) и сжатием Elias-Fano/Varint. Полностью переносимы.
*   **Слияние результатов (RRF) и фильтрация:** Алгоритм слияния и фильтры по метаданным. Полностью переносимы.

### 3. Встроенный ИИ (Embedded AI)
*   **Интеграция ONNX Runtime:** Кроссплатформенная загрузка и инференс эмбеддинг-моделей.
*   **Встроенные токенизаторы:** Переносимые C++ реализации BPE и WordPiece.
*   **Affinity Thread Pool:** Пул потоков. Поддерживает Linux и macOS, под Windows на данный момент работает в режиме fallback (без привязки к ядрам).

## 🔴 Требует доработки для поддержки Windows (Главный приоритет)

### 1. Подсистема хранения (Storage Layer)
*   [x] **Портирование `MmapFile` на Windows API:**
    *   *Текущее состояние:* Использует POSIX `<sys/mman.h>`, `mmap`, `munmap`, `madvise`, `msync`, `ftruncate`.
    *   *Задача:* Добавить Windows-реализацию (`CreateFileMapping`, `MapViewOfFile`, `UnmapViewOfFile`, `FlushViewOfFile`, `SetEndOfFile`).
*   [x] **Портирование `WriteAheadLog` (WAL) на Windows API:**
    *   *Текущее состояние:* Использует POSIX `<unistd.h>`, `open`, `write`, `pread`, `fsync`.
    *   *Задача:* Перевести на стандартные C++ потоки (`std::fstream`), портативные функции C-Runtime (`_open`, `_write`, `_commit`) или Win32 API (`CreateFile`, `WriteFile`, `ReadFile` с `OVERLAPPED`).

### 2. Сетевой транспорт (Network Layer)
*   [x] **Создание портативного сетевого бэкенда (TCP Server):**
    *   *Текущее состояние:* Сетевой сервер жестко завязан на Linux-специфичный интерфейс `io_uring` ([iouring_server.cpp](file:///f:/projects/Custom-hybrid-RAG/src/network/iouring_server.cpp)).
    *   *Задача:* Добавить кроссплатформенный сетевой бэкенд (например, на `Boost.Asio` или через стандартные сокеты Berkeley/Winsock), который будет собираться на Windows, оставив `io_uring` как оптимизацию под Linux.

### 3. Сборочная система
*   [x] **Адаптация `CMakeLists.txt` под MSVC и Windows:**
    *   Исключить обязательное требование `liburing` на Windows.
    *   Настроить автоматическое подключение зависимостей (RocksDB, roaring, onnxruntime) через Windows-версию `vcpkg`.
