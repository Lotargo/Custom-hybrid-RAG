# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Распределенный Гибридный RAG-движок (C++20/23)

## 1. Общие архитектурные требования
*   **Язык и стандарты:** C++20 или C++23. Использование современных возможностей (`std::span`, `Concepts`, `Coroutines` где применимо).
*   **Сборка:** CMake.
*   **Зависимости:** Минимальные. Внешние библиотеки только для узкоспециализированных задач (ONNX Runtime / GGML для инференса, Boost.Asio для сети, GTest/GBenchmark для тестов).
*   **Целевая ОС:** Linux-first (оптимизация под `epoll`, `mmap`, `madvise`), совместимость с POSIX.

---

## Модуль 1: Математическое ядро и Векторные операции (Core Math)
**Цель:** Обеспечить максимально быстрое вычисление дистанций между векторами без накладных расходов.

**Задачи к реализации:**
1.  **SIMD-оптимизированные метрики:** Реализовать функции расчета Cosine Similarity, L2 Distance и Dot Product для массивов `float32` и `int8` (квантованные векторы).
2.  **Архитектурная независимость (SIMD Abstraction Layer):** Разработать слой абстракции для кросс-платформенной поддержки аппаратного ускорения (x86_64, ARM NEON, WebAssembly SIMD и т.д.). Это обеспечит работу движка на мобильных устройствах (Android, iOS), микрокомпьютерах (Raspberry Pi) и других архитектурах вне стационарных ПК.
3.  **Аппаратная векторизация:** Использовать интринсики AVX2 и AVX-512 (с фоллбеком на скалярные вычисления, если процессор не поддерживает).
4.  **Абстракция типов данных:** Использовать `std::span<const float>` для передачи данных без копирования (Zero-copy).
5.  **Бенчмаркинг:** Написать тесты производительности (Google Benchmark), доказывающие пропускную способность вычислений не ниже пропускной способности L1/L2 кэша процессора.

## Модуль 2: Подсистема хранения и Управление памятью (Storage Layer)
**Цель:** Отказ от полной загрузки базы в RAM в пользу Tiered Storage (RAM + NVMe SSD).

**Задачи к реализации:**
1.  **Memory-Mapped Storage:** Реализовать класс-обертку над POSIX `mmap()`. Класс должен позволять проецировать бинарные файлы размером >100 ГБ в виртуальную память.
2.  **Управление кэшем ОС:** Интегрировать системные вызовы `madvise` (например, `MADV_RANDOM` для векторов, `MADV_WILLNEED` для горячих индексов) для управления поведением Page Cache.
3.  **Хранилище метаданных:** Реализовать легковесное K/V хранилище на основе архитектуры LSM-tree (Log-Structured Merge-tree) или B-Tree для хранения атрибутов документов и JSON-метаданных.
4.  **Write-Ahead Log (WAL):** Разработать механизм журналирования всех операций записи на диск (append-only) для защиты от потери данных при краше сервера.

## Модуль 3: Поисковые индексы (Retrieval Engine)
**Цель:** Реализация алгоритмов гибридного поиска (Векторы + Текст) слиянием результатов.

**Задачи к реализации:**
1.  **Векторный индекс (HNSW / IVF-PQ):** Разработать структуру графа HNSW. Требования: 
    *   Потокобезопасная вставка (lock-free или fine-grained locks).
    *   Сохранение и загрузка состояния графа на диск в бинарном формате.
2.  **Лексический индекс (Inverted Index / BM25):** Реализовать инвертированный индекс. [x]
    *   Поддержка токенизации текста (стемминг, удаление стоп-слов). [x]
    *   Сжатие постинг-списков (например, алгоритмы Elias-Fano или Varint). [x]
3.  **Фильтрация по метаданным:** Реализовать Bloom-фильтры и Roaring Bitmaps для сверхбыстрого отсечения документов, не подходящих под жесткие условия (например, `date > 2024`).
4.  **Слияние результатов (RRF):** Написать модуль Reciprocal Rank Fusion, который будет нормализовать скоры от векторного и лексического поиска, выдавая итоговый топ-K документов.

## Модуль 4: Локальный Machine Learning (Embedded AI)
**Цель:** Автономное создание эмбеддингов и реранжирование прямо в процессе (in-memory), исключая сетевые походы в Python-микросервисы.

**Задачи к реализации:**
1.  **Интеграция ONNX Runtime / GGML:** Подключить C++ API для работы с моделями.
2.  **Встроенный Токенизатор:** Реализовать BPE (Byte-Pair Encoding) и WordPiece токенизаторы на C++ для подготовки текстов перед подачей в модели (совместимость с форматами HuggingFace `tokenizer.json`). [x]
3.  **Пул инференса (Inference Pool):** Реализовать Thread Pool с привязкой потоков (Thread Affinity) к конкретным ядрам CPU для параллельного инференса эмбеддинг-моделей (например, `bge-m3`). [x]
4.  **Модуль Reranking:** Интегрировать поддержку Cross-Encoder моделей для финального переупорядочивания топ-100 результатов, полученных от HNSW/BM25.

## Модуль 5: Сетевой Транспорт и API (Network Layer)
**Цель:** Сверхбыстрый I/O без оверхеда HTTP/gRPC.

**Задачи к реализации:**
1.  **Бинарный протокол:** Спроектировать кастомный TCP-протокол. Формат пакета: `[Magic Byte][Длина (4 байта)][ID Команды (1 байт)][Payload]`.
2.  **Асинхронный TCP-сервер:** Написать сервер на базе Boost.Asio (или напрямую на `io_uring`/`epoll`).
    *   Пул соединений (Connection Pool).
    *   Отсутствие аллокаций памяти (Zero-Allocation) на горячем пути приема пакетов (использование Ring Buffers).
3.  **C-API (FFI):** Разработать плоский C-интерфейс (`extern "C"`) с компиляцией движка в `.so`/`.dll`. Предоставить заголовочный файл `sonatadb.h` для генерации биндингов (ctypes/cgo) под Python/Go/PHP.

## Модуль 6: Распределенность и Мультитенантность (Distributed & Enterprise Features)
**Цель:** Подготовка архитектуры к масштабированию и SaaS-модели с первого дня.

**Задачи к реализации:**
1.  **Изоляция тенантов (Multitenancy):** Реализовать концепцию `Namespaces`. Каждый Namespace имеет свою директорию на диске (изоляция данных) и свои инстансы графов в памяти.
2.  **Шардирование (Consistent Hashing):** Написать алгоритм распределения данных по узлам (нодам) кластера на основе хеш-кольца (Ring Hashing). Реализовать механизм маршрутизации запроса: нода-приемник понимает, на каких шардах лежат данные, опрашивает их по TCP, агрегирует и возвращает ответ.
3.  **Кластерный Консенсус (Raft):** Интегрировать минималистичную реализацию алгоритма Raft для выбора лидера (Master node) и синхронизации конфигурации кластера (Topology map).
4.  **Heartbeat & Discovery:** Реализовать фоновый процесс обмена UDP-пингами (Gossip protocol) между узлами для автообнаружения живых нод в локальной сети.
